#### Keyboard Input
When a user produces *keyboard input*, windows can generate several different messages:
- `WM_KEYDOWN` a non-system key was pressed or repeated
- `WM_KEYUP` a non-system key was released
- `WM_CHAR` character input was produced (discussed in [[1.3.3 Messages]])
- `WM_SYSKEYDOWN` a system key was pressed (such as ALT + a key)

For `WM_KEYDOWN` the `wParam` contains a virtual key code identifying the key:
```cpp
LRESULT CALLBACK window_proc(HWND hwndm, UINT m, WPARAM wp, LPARAM lp) {
	switch (m) {
		case WM_KEYDOWN:
			if (wp == VK_F7)
				return 0;
			break;
		case WM_DESTROY:
			PostQuitMessage(0);
			return 0;
	}
	return DefWindowProcW(hwnd, m, wp, lp);
}
```
- When a key is held, windows receives `WM_KEYDOWN` on the initial press and during the hold (repeated and pressed).
- Windows provides us information in `lParam` that lets us distinguish an initial press from a repeating press. 
#### Keyboard Focus
Windows generally only delivers messages to windows has the current *keyboard focus*. And so, for an application to respond keyboard inputs while it does not have keyboard focus uses hotkeys, via `RegisterHotkey()`, which allows windows to notify the application of when a registered hotkey was pressed. 
- Messages produced by a registered system wide hotkey are `WM_HOTKEY` messages.
- Messages produced by keyboard input to a keyboard focused application are `WM_KEYDOWN` messages.
#### Mouse Input
Mouse input is handled similarly to keyboard input, with the cursor coordinates (relative the window client) in `lParam`:
- `WM_MOUSEMOVE` cursor moved
- `WM_LBUTTONDOWN`/`WM_RBUTTONDOWN` left/right mouse button pressed
- `WM_LBUTTONUP`/`WM_RBUTTONUP` left/right mouse button released
- `WM_MOUSEHWEEL` mouse wheel scrolled

We can extract the coordinates using two macros:
```cpp
#include <windowsx.h>

int x = GET_X_LPARAM(lp);
int y = GET_Y_LPARAM(lp);
```
`wParam` on the other hand contains flags describing which mouse buttons or modifier keys are held:
- `MK_LBUTTON` left mouse button held
- `MK_RBUTTON` right mouse button held
- `MK_CONTROL` ctrl held
- `MK_SHIFT` shift held

We can check these flags using bitwise AND:
```cpp 
bool left_down = (wp & MK_LBUTTON) != 0;
```
#### Window Focus Events
Windows provides two messages which tell us when the window gains or loses focus:
- `WM_SETFOCUS` the window gained keyboard focus
- `WM_KILLFOCUS` the window lost keyboard focus
it is important to note that keyboard focus and window focus are correlated but not identical.
It is also important to track keyboard focus, because of several reasons. The important of being if the user presses and the application receives `WM_KEYDOWN` then switches windows (loses keyboard focus for the application), the application will not receive the corresponding `WM_KEYUP`:
```cpp
bool has_focus = false;

LRESULT CALLBACK window_proc(HWND hwnd, UINT m, WPARAM wp, LPARAM lp) {
    switch (m) {
        case WM_SETFOCUS:
            has_focus = true;
            return 0;
            
        case WM_KILLFOCUS:
            has_focus = false;
            return 0;
    }
    
    return DefWindowProcW(hwnd, m, wp, lp);
}
```
#### Window Resizing
When a window's size changes, windows can send a `WM_SIZE` message, where `wParam` describes the type of resizing and `lParam` describes the new client area width and height, packed into one value:
```cpp
case WM_SIZE: {
	if (wp == SIZE_MINIMIZED)
		return 0;
	
	UINT width = LOWORD(lp);
	UINT height = HIWORD(lp);
	
	// update interface dimensions
	
	return 0;
}
```
#### Mouse Capture
Mouse capture allows a window to continue receiving mouse input when the cursor moves outside its client area.
- `SetCapture(hwnd)` captures mouse input for a window.
- `ReleaseCapture()` releases mouse capture.
- `WM_CAPTURECHANGED` notifies a window when it loses mouse capture.
This is useful for dragging UI elements, where the mouse may leave the window before the button is released.
